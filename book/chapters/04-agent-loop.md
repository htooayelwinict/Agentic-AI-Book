# အခန်း ၄ - Agent Loop

### အဆုံးမရှိသော သံသရာနှင့် ဆင်ခြင်တုံတရား

အရင်အခန်းတွေမှာ Agent တစ်ခုရဲ့ "ဦးနှောက်" နဲ့ "လက်" အကြောင်း ပြောခဲ့ပါတယ်။ ဒါပေမယ့် ဒီအစိတ်အပိုင်းတွေကို စုလိုက်ရုံနဲ့ အလုပ်လုပ်တတ်တဲ့ Agent ဖြစ်မလာသေးပါဘူး။ တကယ် အလုပ်လုပ်ဖို့ **Agent Loop** လို့ ခေါ်တဲ့ ကွင်းဆက် တစ်ခု လိုပါတယ်။ လူတစ်ယောက် အလုပ်တစ်ခု လုပ်တဲ့အခါ "စဉ်းစားတယ်၊ လုပ်တယ်၊ လွဲတယ်၊ ပြန်ပြင်တယ်" ဆိုတဲ့ အဆင့်တွေ ရှိသလိုပါပဲ။

ရိုးရိုး Software က မျဉ်းဖြောင့်အတိုင်း သွားပါတယ်။ အမှားတွေ့ရင် ရပ်သွားပါတယ်။ Agentic AI က ထူးခြားတာက အမှားတွေ့တဲ့အခါ "ဘာကြောင့် မှားသလဲ" ပြန်စဉ်းစားနိုင်တာ (Self-Reflection) နဲ့ ကျော်ဖို့ နည်းသစ် ရှာနိုင်တာပါ။ ဒါကို **Reasoning Loop** လို့ ခေါ်ပါတယ်။

ဒီကွင်းဆက်က Agent ကို "စာရေးတော်" အဆင့်ကနေ "ပြဿနာ ဖြေရှင်းသူ" အဆင့်ကို တင်ပေးလိုက်တာပါ။

### ReAct: စဉ်းစားခြင်းနှင့် လုပ်ဆောင်ခြင်း၏ ပေါင်းစပ်မှု

Agentic AI လောကမှာ အနာမည်ကြီးဆုံး နည်းလမ်းတစ်ခုက **ReAct (Reason + Act)** ပါ။ Agent ကို အလုပ်တစ်ခု မလုပ်ခင် "ငါ ဘာလုပ်မလဲ" အရင် စဉ်းစားခိုင်းတယ် (Thought)။ ပြီးမှ လုပ်ခိုင်းတယ် (Action)။ ရလာတဲ့ ရလဒ်ကို ကြည့်ခိုင်းတယ် (Observation)။ ဒီသုံးခုကို အလုပ်ပြီးသည်အထိ ထပ်ခါထပ်ခါ ပတ်ပါတယ်။

ဥပမာ - Agent ကို "မြန်မာနိုင်ငံရဲ့ လက်ရှိ လူဦးရေ ရှာပေးပါ" လို့ ခိုင်းလိုက်တယ် ဆိုပါစို့။

၁။ **Thought:** "ငါ့ မှတ်ဉာဏ်ထဲမှာ လက်ရှိ လူဦးရေ အတိအကျ မရှိဘူး။ Search tool နဲ့ ရှာမှ ရမယ်။"

၂။ **Action:** `web_search("Myanmar population 2024")` ဆိုတဲ့ Tool ကို ခေါ်တယ်။

၃။ **Observation:** ရလဒ်ထဲမှာ "၅၅ သန်းကျော်" လို့ တွေ့တယ်။

၄။ **Thought:** "အချက်အလက် ရပြီ။ ဒါပေမဲ့ ဒါ တရားဝင် သန်းခေါင်စာရင်းလား ထပ်စစ်သင့်တယ်။"

ဒီလိုနဲ့ Agent က ကိုယ့်အလုပ်ကို ကိုယ့်ဘာသာ ပြန်စစ်ရင်း ပန်းတိုင်ဆီ သွားပါတယ်။ အလုပ်ခိုင်းတဲ့အခါ "မင်း ဘာလုပ်နေလဲ ငါ့ကို အမြဲ ပြောပြ" လို့ စည်းကမ်း ထုတ်ထားတာနဲ့ တူပါတယ်။ ကိုယ် ဘာလုပ်နေလဲ ထုတ်ပြောခိုင်းတာကို **Chain of Thought** လို့ ခေါ်ပါတယ်။ ဒါက model ကို အမြဲ ပိုတော်သွားစေတာ မဟုတ်ပါဘူး။ အဓိက အသုံးဝင်တာက ကျွန်တော်တို့ ဘက်ကပါ။ Agent ဘယ်နေရာမှာ လမ်းလွဲသွားလဲ log ထဲမှာ ပြန်ကြည့်လို့ရတယ်။ Tool ခေါ်ဖို့ ဘာကြောင့် ဆုံးဖြတ်ခဲ့လဲ သိရတယ်။ Hallucination ကိုတော့ ဒါတစ်ခုတည်းနဲ့ မကာကွယ်နိုင်ပါဘူး။ Tool result ကို ပြန်စစ်တာ (Observation) နဲ့ Verifier (အခန်း ၈) က ပိုအရေးကြီးပါတယ်။

### Loop ကို code အနေနဲ့ ကြည့်ရင်

စာနဲ့ ပြောရင် ရှုပ်သလို ထင်ရပေမယ့် code အနေနဲ့ ကြည့်ရင် Agent Loop က ဒီလောက်ပါပဲ။ ဒါက pseudocode ပါ။ Library တစ်ခုခုရဲ့ code မဟုတ်ပါဘူး။

```python
def run_agent(goal, tools, max_iterations=10):
    history = [goal]

    for step in range(max_iterations):
        # 1. Thought: model ကို history ပေးပြီး နောက်တစ်လှမ်း မေးတယ်
        decision = llm(history, tools)

        # 2. Model က အဖြေ ပြီးပြီလို့ ပြောရင် ရပ်တယ်
        if decision.is_final_answer:
            return decision.answer

        # 3. Action: model ရွေးလိုက်တဲ့ tool ကို ကျွန်တော်တို့ code က run တယ်
        result = tools[decision.tool_name](**decision.arguments)

        # 4. Observation: ရလဒ်ကို history ထဲ ပြန်ထည့်ပြီး loop ဆက်ပတ်တယ်
        history.append(decision)
        history.append(result)

    return "ကြိမ်ရေ ကန့်သတ်ချက် ပြည့်သွားပါပြီ။ လူ ပြန်စစ်ပေးပါ။"
```

ဒီ code ထဲမှာ အရေးကြီးတဲ့ အချက် သုံးချက် ရှိပါတယ်။

- Model က tool ကို ကိုယ်တိုင် run တာ မဟုတ်ပါဘူး။ "ဒီ tool ကို ဒီ argument နဲ့ ခေါ်ချင်တယ်" လို့ ပြောတာပါ။ Run တာက ကျွန်တော်တို့ code ပါ။ ဒါကြောင့် tool တစ်ခု မ run ခင် permission စစ်ဖို့ နေရာ ရှိပါတယ်။ အခန်း ၉ မှာ ဒီနေရာကို အသေးစိတ် ပြောပါမယ်။
- Observation ကို history ထဲ ပြန်ထည့်မှ loop က အလုပ်လုပ်ပါတယ်။ ရလဒ်ကို ပြန်မပေးရင် model က အစအတိုင်းပဲ ပြန်စဉ်းစားပါလိမ့်မယ်။
- `max_iterations` က အလှ မဟုတ်ပါဘူး။ နောက်အပိုဒ်မှာ ဘာကြောင့်လဲ ပြောပါမယ်။

LangGraph, DeepAgents လို library တွေက ဒီ loop ကို graph, middleware, checkpoint တွေနဲ့ ဖုံးထားပါတယ်။ ဒါပေမယ့် အထဲမှာ ပတ်နေတာက ဒီ loop ပါပဲ။ အခန်း ၁၂ ကနေ ၁၅ အထိ case study တွေ ဖတ်တဲ့အခါ ဒီ loop ကို ပြန်ရှာကြည့်ပါ။

### အမှားကို အခွင့်အလမ်းအဖြစ် ပြောင်းလဲခြင်း

Agent တစ်ခု ကောင်းမကောင်း တိုင်းတဲ့အခါ အလုပ် ဘယ်လောက် မြန်မြန် ပြီးလဲ ဆိုတာထက် အမှားတွေ့ရင် ဘယ်လို တုံ့ပြန်လဲ ဆိုတာက ပိုအရေးကြီးပါတယ်။ ဥပမာ - Agent က Tool တစ်ခု ခေါ်လိုက်တယ်၊ Tool က Error ပြန်တယ် ဆိုပါစို့။ ရိုးရိုး Software ဆိုရင် "Error: 404" ပြပြီး ရပ်သွားပါလိမ့်မယ်။

Agentic Loop ထဲမှာတော့ ဒီ Error က Agent အတွက် "အချက်အလက်သစ်" (Observation) တစ်ခု ဖြစ်လာပါတယ်။ Agent က "ဪ ဒီနည်းက မရဘူး။ တစ်ခြားနည်းနဲ့ ကြိုးစားကြည့်မယ်" လို့ ဆုံးဖြတ်နိုင်ပါတယ်။ ဒါကို **Error Recovery** လို့ ခေါ်ပါတယ်။ ဒီစွမ်းရည်ကြောင့် Agent က လူ မကြီးကြပ်ဘဲ နာရီပေါင်းများစွာ ဆက်အလုပ်လုပ်နိုင်တာပါ။ Agent ရဲ့ "ဇွဲ" ပေါ့။

ဒါပေမယ့် ဒီ "ဇွဲ" က တစ်ခါတစ်လေ အန္တရာယ် ရှိပါတယ်။ မဖြေရှင်းနိုင်တဲ့ ပြဿနာကို Agent က ထပ်ခါထပ်ခါ ကြိုးစားနေရင် **Infinite Loop** ထဲ ရောက်သွားပြီး API ကုန်ကျစရိတ် တက်သွားပါလိမ့်မယ်။ ဒါကြောင့် engineer အနေနဲ့ **Max Iterations** ကို မဖြစ်မနေ ထည့်ရပါတယ်။ အပေါ်က code ထဲက `max_iterations=10` ဆိုတာ "၁၀ ကြိမ် ကြိုးစားလို့ မရရင် ရပ်ပြီး လူကို ပြန်မေး" ဆိုတဲ့ အမိန့်ပါ။

Max iterations တစ်ခုတည်းနဲ့လည်း မလုံလောက်ပါဘူး။ Agent က တစ်ခါခေါ်ပြီးသား tool ကို argument အတူတူနဲ့ ထပ်ခေါ်နေရင် ကြိမ်ရေ မပြည့်သေးပေမယ့် loop ပတ်နေပြီ ဖြစ်နိုင်ပါတယ်။ အခန်း ၁၃ မှာ Travis-2 က ဒါကို semantic loop detection နဲ့ ဘယ်လို ဖမ်းလဲ ကြည့်ရပါမယ်။

### စဉ်းစားဆင်ခြင်မှု၏ ကုန်ကျစရိတ်

Loop တစ်ပတ် ပတ်တိုင်း LLM ဆီ Token တွေ ပို့ရပါတယ်။ Agent ပိုစဉ်းစားလေ ပိုက်ဆံ ပိုကုန်လေပါ။ အချိန်လည်း ပိုကြာပါတယ်။ တော်တဲ့ Agent လိုချင်ပေမယ့် ရိုးရိုးမေးခွန်းကို ၁၅ မိနစ် စဉ်းစားနေတဲ့ Agent ကတော့ လက်တွေ့ သုံးမရပါဘူး။

ဒါကြောင့် **Efficiency** ကိုလည်း စဉ်းစားရပါတယ်။ နည်းလမ်း အချို့ ဒီမှာပါ။

- အရာရာကို loop မပတ်ဘဲ ခက်တဲ့ အဆင့်မှာပဲ ပတ်ပါ။ Code format ပြင်တာလို အလုပ်ကို loop ပတ်ဖို့ မလိုပါဘူး။
- အဆင့်အချို့မှာ သေးပြီး မြန်တဲ့ model (Small Language Model) ကို သုံးပါ။ "ဒီ email အရေးကြီးလား" ခွဲတာမျိုးကို အကြီးဆုံး model နဲ့ လုပ်ဖို့ မလိုပါဘူး။
- Tool result ကို history ထဲ အကုန် ထည့်မနေပါနဲ့။ လိုတာလောက်ပဲ ထည့်ပါ။ ဒါကို အခန်း ၇ Context Engineering မှာ အသေးစိတ် ပြောပါမယ်။

"စာရေးတော်" ကို ခိုင်းတဲ့အခါ အလုပ် အတိမ်အနက်အလိုက် လူမှန် နေရာမှန် ခွဲပေးရတာနဲ့ တူပါတယ်။

### နိဂုံး - ကွင်းဆက်၏ အဆုံးသတ်

Agentic Loop က Agentic AI ရဲ့ နှလုံးခုန်သံပါ။ စက်ကို "စဉ်းစားတတ်သူ" ဖြစ်အောင် လုပ်ပေးတာ ဒီ loop ပါ။ ဒါပေမယ့် နှလုံးခုန်သံ စည်းချက် ကျရပါမယ်။ အလွန်အကျွံ ခုန်ရင် စနစ် တစ်ခုလုံး ပူသွားနိုင်တယ်။ နှေးလွန်းရင်လည်း အလုပ် မတွင်ပါဘူး။

နောက်အခန်းမှာ ဒီ Loop ကို စနစ်တကျ ထိန်းပေးမယ့်၊ Agent ရဲ့ မှတ်ဉာဏ်နဲ့ ပတ်ဝန်းကျင်ကို စီမံပေးမယ့် **Agent Harness** အကြောင်း ဆက်ပြောပါမယ်။ ကျွန်တော်တို့ "စာရေးတော်" အတွက် လုံခြုံပြီး အလုပ်တွင်တဲ့ "ရုံးခန်း" တစ်ခု ဆောက်ပေးတာပါ။

**စာဖတ်သူအတွက် Source Notes:**

- **ReAct Pattern:** A prompting technique that combines reasoning traces and task-specific actions in an interleaved manner.
- **Chain of Thought (CoT):** A method that encourages the model to break down complex problems into intermediate steps.
- **Self-Reflection:** A technique where the model critiques its own previous outputs to improve accuracy.
- **Token Usage & Latency:** The primary constraints in designing agentic loops, requiring a balance between reasoning depth and cost.
- **Stop Sequences:** Technical markers used to signal the end of a model's thought process or action call.
- **Max Iterations / Loop Detection:** Hard stop on the number of loop turns, plus detection of repeated identical tool calls, so a stuck agent fails closed instead of spending indefinitely.
